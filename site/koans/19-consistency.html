快取一致性

兩個快取副本。一個說是。一個說否。誰在說真話？

概念

快取一致性是指快取中的資料與原始資料來源（source of truth）之間的同步程度。當資料被更新時，快取可能仍持有舊值。

最終一致性 (Eventual Consistency)：給定足夠的時間，所有快取最終會收斂到相同的值。Read-your-writes 一致性：寫入後立即讀取能看到自己的寫入結果。

互動模擬

模擬兩個伺服器節點各自有快取，共享一個資料庫。在 Server A 寫入資料，觀察 Server B 如何變得不一致，然後透過失效傳播修復。

洞察
CAP 定理也適用於快取。大多數分散式快取選擇可用性 (Availability) 和分區容忍性 (Partition Tolerance)，而犧牲嚴格一致性。

常見策略：
• Write-through：寫入同時更新快取和 DB
• Write-behind：先更新快取，異步寫 DB
• Cache invalidation + Pub/Sub：寫入 DB 後廣播失效訊息

選擇哪種策略取決於你能容忍多長時間的不一致。
