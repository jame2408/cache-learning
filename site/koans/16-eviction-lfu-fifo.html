LFU 與 FIFO 淘汰策略

LRU 看時間，LFU 看次數。FIFO 只看順序。哪一個最公平？

概念

LFU（Least Frequently Used）淘汰存取次數最少的項目。它假設：過去被經常使用的資料，未來也可能被使用。

FIFO（First In First Out）淘汰最先進入快取的項目，不管它被存取了多少次。簡單、可預測，但可能淘汰仍然有用的資料。

思考
什麼時候 FIFO 可能比 LRU 更適合？
當存取模式均勻且簡單性更重要時
當項目被頻繁存取時

洞察
現代快取常使用自適應演算法，如 ARC（Adaptive Replacement Cache）或 W-TinyLFU（用於 Java 的 Caffeine 函式庫）。

W-TinyLFU 結合了 LRU 和 LFU 的優點：用一個小型的「視窗 LRU」來捕捉新進資料，再用頻率過濾器決定是否提升到主快取。這讓它在各種工作負載下都能表現優異。
