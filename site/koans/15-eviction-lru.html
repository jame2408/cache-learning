LRU 淘汰策略

空間有限。師父說：「留下你最近用過的，忘記你久未碰觸的。」

理解

LRU（Least Recently Used，最近最少使用）是最常見的快取淘汰策略。當快取空間已滿，需要加入新項目時，移除最久未被存取的項目。

其背後的假設是：最近被使用過的資料，在不久的將來更可能再次被使用。這個假設在大多數場景中成立，因此 LRU 成為最廣泛採用的淘汰策略。

資料結構

高效的 LRU 實作使用 HashMap + 雙向鏈結串列，達到 O(1) 的 get 和 put 操作。

思考
最佳 LRU 實作的時間複雜度是多少？
O(1)，使用 HashMap + 雙向鏈結串列
O(n)，使用陣列
O(log n)，使用樹
洞察
LRU 透過 HashMap（O(1) 查找）加上雙向鏈結串列（O(1) 插入/刪除/移動到頭部）實現所有操作 O(1)。被廣泛使用於 Linux 頁面快取、大多數 Web 框架、CDN，以及 Redis 的淘汰策略中。變體包括 LRU-K（考慮最近 K 次存取）和分段 LRU（分為「保護」與「觀察」區）。
