Koan 04

Read-Through 快取模式

弟子說：「我不想自己管快取。」師父說：「那就讓快取自己管自己。」

概念

Read-Through 模式與 Cache-Aside 類似，但有一個關鍵區別：在 Read-Through 中，快取層本身負責在未命中時從資料庫取得資料。應用程式只需要與快取溝通，不需要知道資料庫的存在。

這簡化了應用程式的程式碼，但也意味著你的應用程式與快取層的耦合更緊密。

比較圖解

點擊下方卡片，觀察兩種模式中資料流的差異。

Cache-Aside 模式
1. 應用程式 → 快取（查詢）
2. 快取 → 應用程式（未命中）
3. 應用程式 → 資料庫（讀取）
4. 應用程式 → 快取（寫入）
Read-Through 模式
1. 應用程式 → 快取（查詢）
2. 快取 → 資料庫（自動讀取）
3. 快取自動儲存資料
4. 快取 → 應用程式（返回資料）

洞察
Read-Through 把「從哪裡取資料」的邏輯從應用程式移到了快取層。

好處：應用程式的程式碼更簡單——它只需要說「給我這個資料」，不需要關心資料從哪來。

代價：你的快取層變得更複雜，而且應用程式對快取層的依賴更深。如果快取層掛了，應用程式不知道如何直接去資料庫取資料。

常見的 Read-Through 實作包括 AWS DAX（DynamoDB 的 Read-Through 快取）和很多 ORM 框架的內建快取。
