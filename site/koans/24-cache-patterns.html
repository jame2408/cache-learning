Koan 24

進階快取模式總覽

「學會了每一招，才能忘記招式，隨心而用。」

理解

到目前為止，你已經學過多種快取模式：Cache-Aside、Write-Through、Write-Behind、Read-Through，以及各種淘汰策略。每種模式都有其最佳適用場景。真正的技藝在於——根據實際需求，選擇並組合正確的模式。

決策流程圖

回答以下問題，系統會為你推薦最適合的快取策略。

📚 讀取為主
讀取請求遠多於寫入
✍ 寫入為主
寫入請求頻繁或與讀取相當
⏳ 容許短暫過時
資料可以有幾秒的延遲
🔒 嚴格一致性
資料必須即時準確
📌 同步寫入
每次寫入都必須持久化
⚡ 非同步寫入
可以接受短暫的寫入延遲
推薦：Cache-Aside + TTL

最適合讀取為主、可容許短暫過時的場景。應用自行管理快取：先查快取，未命中再查資料庫並填充。搭配 TTL 自動過期和 LRU 淘汰策略。

def get(key):
  val = cache.get(key)
  if val is None:
    val = db.query(key)
    cache.set(key, val, ttl=60)
  return val
推薦：Read-Through + Write-Through

適合需要嚴格一致性的讀取場景。快取層自動從資料庫載入數據，寫入時同步更新快取和資料庫，確保快取始終是最新的。

推薦：Write-Through

適合寫入頻繁且需要持久化保證的場景。每次寫入同時更新快取和資料庫，保證資料不會丟失。延遲較高但一致性最強。

推薦：Write-Behind (Write-Back)

適合寫入頻繁但可接受短暫延遲的場景。寫入先到快取，非同步批量寫回資料庫。吞吐量最高，但有資料丟失風險。

思考

對於一個讀取為主、可容許短暫過時的應用，哪種模式最佳？
Cache-Aside + TTL
Write-Through
不使用快取
洞察
大多數生產系統會組合多種模式。例如：Cache-Aside + TTL + LRU 淘汰 + 分散式快取搭配本地 L1 快取。沒有萬能的快取策略——理解每種模式的取捨，才能設計出最適合你系統的方案。
