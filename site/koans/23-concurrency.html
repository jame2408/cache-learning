Koan 23

快取並發

「兩個執行緒同時讀寫同一個快取鍵。它們都認為自己是對的。」

理解

當多個執行緒或程序同時對同一個快取鍵進行讀取-修改-寫入操作時，就會產生競態條件（Race Condition）。常見問題包括：雙重讀取（Double Read）、遺失更新（Lost Update）、過時讀取（Stale Read）。解決方案包括 CAS（Compare-And-Swap）、分散式鎖和版本控制。

洞察
Redis 透過 WATCH/MULTI/EXEC 支援 CAS 操作。Memcached 內建原生的 CAS 支援。程序內快取可使用語言級別的鎖（如 Java 的 ConcurrentHashMap、Go 的 sync.Mutex）。

選擇正確的並發控制策略取決於你的一致性需求和性能預算。
